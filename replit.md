# Volunteer AI

A community help platform where neighbors help neighbors. Three roles, each with login/register/dashboard.

## Roles

- **User** — posts help requests; reviews volunteer applications; approves or rejects them. Location and contact phone are kept private until a volunteer is approved.
- **Volunteer** — sets up a profile (role title, skills, bio, phone, city, availability, experience); browses open requests in their area; applies with a message; sees the requester's contact info only after being approved.
- **Admin** — pre-seeded account at `admin@volunteerai.app` / `admin123`. Sees totals, status breakdowns, category breakdowns, recent activity, and can drill into any user or volunteer.

## Architecture

- `artifacts/volunteer-ai` — React + Vite single-page app served at `/`. Wouter routes, TanStack Query, Framer Motion (heavy animation throughout), Recharts on admin, sonner toasts, shadcn UI primitives.
- `artifacts/api-server` — Express 5 API at `/api`. Sessions stored in Postgres via `connect-pg-simple` (table `user_sessions`). Auth uses bcryptjs + cookie sessions.
- `lib/api-spec` — OpenAPI source of truth.
- `lib/api-zod`, `lib/api-client-react` — generated by `pnpm --filter @workspace/api-spec run codegen`. Zod schemas exported under namespace `schemas`. React Query hooks exported by name (e.g. `useGetMe`, `useDecideApplication`).
- `lib/db` — Drizzle schema for `users`, `volunteer_profiles`, `requests`, `applications`. Push with `pnpm --filter @workspace/db run push`.

## Visibility rule

`request.location` and `request.contactPhone` are returned only to: the request owner, the approved volunteer for that request, or an admin. Everyone else sees `null`. Implemented in `artifacts/api-server/src/lib/serializers.ts:serializeRequest`.

## Notes for future work

- The session table (`user_sessions`) was created manually because the bundled `connect-pg-simple` cannot find its `table.sql` after esbuild bundling. `createTableIfMissing` is therefore set to `false`. If the schema changes, run the create-table SQL by hand or unbundle the package.
- Demo data seeding is idempotent: it only inserts when there are zero non-admin users.
